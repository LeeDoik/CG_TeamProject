# 스테이지 1까지 구성 (2026-11-11)

팀원의 `src/Default_Project` 엔진(컴포넌트·씬·조명) 위에 제안서의 튜토리얼과 스테이지 1을 올렸다.
게임 코드는 `Game/` 폴더, 레벨은 `Levels/*.txt`에 있다.

## 실행

1. `src/Default_Project/Default_Project.vcxproj`를 Visual Studio로 연다. VS 2026은 `.slnx`를 열어도 된다.
2. **x64 / Debug**로 빌드하고 실행한다(F5).
   - GLEW·GLFW·GLM은 수업 실습과 같은 방식으로 `dependencies/` 폴더와 `OpenGL.props`에서 가져온다. 전역 설치가 필요 없다.
   - VS 2022에서는 툴셋 v143, VS 2026에서는 v145가 자동으로 선택된다.
3. 작업 폴더는 프로젝트 폴더여야 한다(`Shader/`, `Assets/`, `Levels/`를 상대 경로로 읽는다). VS 기본값이 이미 프로젝트 폴더다.

## 조작

| 키 | 동작 |
|---|---|
| A / D | 좌우 이동 |
| Space | 점프 (짧게 누르면 낮게 뜀, 위에서 밟으면 책벌레 처치) |
| W / S | 깊이 이동 (3D에서만) |
| E | 2D ↔ 3D 전환 (0.5초) |
| R / F1 / F2 | 지금 스테이지 다시 / 튜토리얼 / 스테이지 1 (테스트용) |
| F12 | 스크린샷 (`Screenshots/shot_N.bmp`, 보고서용) |
| ESC | 종료 (일시정지 메뉴는 아직 없음) |

창 제목에 HP, 모드, 게이지, 조각 수, 구간 힌트가 나온다. 화면 HUD에는 하트, 게이지, 2D/3D 아이콘, 조각 수가 그려진다.

## 직접 작성할 부분 (제안서 4.2)

`Game/CoreRules.cpp`의 함수 4개다. 게임 쪽은 충돌과 전환을 **이 함수로만** 판단한다.
튜토리얼·스테이지 1을 제안서 설계대로 끝까지 동작시키려고 **네 함수 모두 AI가 임시로 채웠다**(11/11, 팀원 결정).
제안서 4.2대로 면담·발표 전에 직접 다시 작성하고, 아래 확인 방법과 클리어 테스트로 같은 결과가 나오는지 본다.

| 함수 | 하는 일 (지금 AI 임시 코드의 방식) | 확인 방법 |
|---|---|---|
| `BoxesOverlap` | 2D는 x·y 구간만, 3D는 x·y·z 구간을 비교 (AABB) | 클리어 테스트 통과, 튜토리얼 C·스테이지 1 계단을 2D로 지나감 |
| `BlendProjection` | 직교·원근 행렬을 원소별 선형 보간. `GameManager`가 원근 화각을 초점 거리에서 직교 화면과 같은 크기가 되게 맞춰서(돌리 줌) 전환 내내 플레이어 크기가 유지됨 | `POPUP_CAPTURE`로 전환 도중 프레임 캡처 |
| `ChooseDepthFor3D` | 2D 기준 발밑 발판을 찾아, 지금 깊이가 그 발판 안이면 유지, 아니면 발판 깊이 중심으로 | 튜토리얼 C 가운데 발판 위에서 E → 콘솔에 `z 0 → -6`, 떨어지지 않음 |
| `CanReturnTo2D` | 2D 규칙으로 겹치는 발판·벽이 있으면 금지 | 튜토리얼 D 상자 뒤에서 E → `시점 전환 막힘`, 화면 흔들림·빨간 아이콘. 스테이지 1 긴 벽을 한 번에 돌면 게이지 0에서 HP 유지한 채 체크포인트로 |

그 밖에 제안서상 직접 작성할 그래픽스 작업: 반투명 벽과 그림자(알파 블렌딩, 그리기 순서), 등불 점광원 조정.
지금 그림자는 불투명한 납작한 구이고, 벽은 불투명하다.

## 레벨 파일 형식

```
# 주석
name 스테이지 1          # 창 제목에 나오는 이름
page 2                   # 이 스테이지의 조각 번호
next stage1.txt          # 다음 레벨 (없으면 마지막)
killY -7                 # 이보다 아래로 떨어지면 낙사
start x y z              # 시작 발 위치
block  x y z  w h d  [재질]                 # 고정 발판 (중심, 크기)
spike  x y z  w h d
mover  x y z  w h d  재질  ax ay az  주기    # 중심 + (ax,ay,az) * sin(2πt/주기)
worm   x y z  범위  속도                     # 발 위치, x±범위 왕복
checkpoint x y z
fragment   x y z
lamp   x y z  밝기                           # 점광원
hint   x시작 x끝 문장                        # 창 제목 힌트
```

좌표는 x 오른쪽, y 위, z 화면 쪽(+)이다. 블록 한 칸이 1이다. 재질 이름: `Paper`, `Card`, `CardDark`, `Wall`, `Mover`.
플레이어는 0.7 × 1.2 × 0.5이고, 점프 높이는 약 2, 점프 거리는 약 3.5다.

## 자동 플레이 테스트

창을 띄우지 않고 입력 스크립트로 플레이해 볼 수 있다(레벨이나 `CoreRules.cpp`를 고친 뒤 회귀 확인용).

**클리어 테스트** (Debug|x64 빌드 후 프로젝트 폴더에서):

```
powershell -ExecutionPolicy Bypass -File Tests\run_replay.ps1 -Replay Tests\clear_all.txt
powershell -ExecutionPolicy Bypass -File Tests\run_replay.ps1 -Replay Tests\clear_stage1.txt -Level Levels\stage1.txt
```

`clear_all.txt`는 튜토리얼부터 스테이지 1 클리어까지 한 번에 진행한다. 끝에 `페이지 조각 2/4 획득 → 스테이지 클리어`가 나오면 통과다.
11/11 기준 HP 3을 유지한 채 통과했다. 레벨 배치나 이동 수치를 바꾸면 스크립트의 시각도 맞춰 고쳐야 한다.

| 환경 변수 | 뜻 |
|---|---|
| `POPUP_HEADLESS=1` | 창을 숨긴 채 실행 |
| `POPUP_REPLAY=경로` | 입력 스크립트 재생 (`시간 키 down/up`, `시간 quit`) |
| `POPUP_LEVEL=경로` | 첫 레벨 파일 바꾸기 |
| `POPUP_LOG=1` | 0.25초마다 위치·모드·게이지·HP를 콘솔에 출력 |
| `POPUP_CAPTURE=2.0,5.1` | 그 시각(초)에 자동 스크린샷 (전환 중간 프레임 캡처용) |
| `POPUP_CAPTURE_DIR=경로` | 스크린샷 폴더 (기본 `Screenshots`) |

```
# 예: 0.5초에 오른쪽으로 걷기 시작, 1.2초에 점프, 5초에 종료
0.5 D down
1.2 SPACE down
1.5 SPACE up
5 quit
```
